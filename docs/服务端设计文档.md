# MergeGame 服务端设计文档

## 架构

```
┌─────────────────────────┐        HTTP/JSON        ┌──────────────────────────┐
│   Godot Client          │ ◄─────────────────────► │   Game Server            │
│                         │                         │                          │
│   表现 + 即时动画        │   REST API               │   Node.js + Express      │
│   乐观 UI + 回滚         │                         │   TypeScript             │
│                         │   POST /api/game/merge   │                          │
│   CloudService    (新)   │   ────────────────────►  │   权威游戏逻辑            │
│   SaveManager     (重写) │   ◄────────────────────  │   JSON 文件存储           │
│   MergeService    (重写) │   200 { result }         │   → IStorage 接口可替换   │
│   LoginScreen     (新)   │                         │                          │
└─────────────────────────┘                         └──────────────────────────┘
```

### 核心原则

- **强制登录** — 启动→LoginScreen→认证→进入游戏
- **服务端权威** — 合并/制作由服务端执行，客户端只做表现
- **乐观 UI** — 操作先播动画，服务端确认后数据落地；拒绝则回滚
- **存储解耦** — 通过 `IStorage` 接口操作数据，切换数据库只需新增实现

## API 接口

| 方法 | 路径 | Body | 响应 | 说明 |
|------|------|------|------|------|
| GET | `/api/health` | — | `{ status: "ok" }` | 健康检查 |
| POST | `/api/auth/login` | `{ device_id }` | `{ token, user }` | 设备 ID 登录/注册 |
| GET | `/api/game/state` | — | `{ score, grid, cultivation, version }` | 拉取当前游戏状态 |
| POST | `/api/game/merge` | `{ from:[c,r], to:[c,r], version }` | `{ ok, new_score, new_version, result_id }` | 执行合并 |
| POST | `/api/game/spawn` | `{ launcher_pos:[c,r], version }` | `{ ok, spawned_id, target_col, target_row, new_version }` | 发射器生成 |
| POST | `/api/game/craft/add` | `{ table_col, table_row, ingredient_id, version }` | `{ ok, matched, new_version }` | 添加材料到制作台 |
| POST | `/api/game/craft/start` | `{ table_col, table_row, version }` | `{ ok, recipe_id, craft_time, new_version }` | 开始制作 |
| POST | `/api/game/craft/retrieve` | `{ table_col, table_row, version }` | `{ ok, result_id, new_version }` | 取出成品 |
| POST | `/api/game/cultivate` | `{ action, pill_id, version }` | `{ ok, cultivation, new_version }` | 修炼操作（突破） |
| GET | `/api/game/leaderboard` | `?limit=50` | `{ entries[] }` | 排行榜 |

### 通用错误响应

| 状态码 | error | 说明 |
|--------|-------|------|
| 400 | `invalid_params` | 请求参数格式错误 |
| 400 | `out_of_bounds` | 坐标超出棋盘范围 |
| 400 | `item_id_mismatch` | 两个物品ID不同，无法合并 |
| 400 | `group_id_mismatch` | 两个物品不同组，无法合并 |
| 400 | `already_max_level` | 物品已达最高等级 |
| 401 | `missing_authorization` | 缺少 Authorization header |
| 401 | `invalid_token` | Token 无效或过期 |
| 404 | `no_game_state` | 未找到游戏状态 |
| 409 | `version_mismatch` | 版本冲突，需先同步最新状态 |

## 乐观锁版本控制

每次操作携带 `version` 参数，服务端校验：
- 客户端 version == 服务端 version → 执行操作，version+1
- 客户端 version != 服务端 version → 返回 409，客户端需重新拉取状态

## 游戏引擎 (game_engine.ts)

内嵌完整物品配置（从 `config/items.json` 加载），提供：

- **合并** — 验证 group_id+id 匹配、下一级存在 → 执行 → 返回新物品+分数
- **生成** — 验证发射器 → 按权重随机 → BFS 找最近空格
- **制作** — 配方匹配（精确计数匹配）、状态机转换
- **修炼** — 突破验证（境界、丹药检查）
- **工具** — BFS 寻空格、棋盘边界检查、状态哈希

## 日志系统

所有日志带标签前缀，便于追踪：

| 标签 | 范围 | 示例 |
|------|------|------|
| `[server]` | 启动/配置 | `[server] Using JSON file storage: ./data` |
| `[engine]` | 游戏逻辑 | `[engine] merge: 凡草x2 -> 灵草 \| score +10` |
| `[auth]` | 认证 | `[auth] new user registered: u_xxx (device=xxx)` |
| `[game]` | 请求处理 | `[game] spawn: ok, saved` |
| `[http]` | HTTP请求 | `[http] POST /merge -> 200 (3ms)` |

## 操作流程：合并

```
客户端                           服务端
  │                                │
  ├─ 拖拽 A → B                    │
  ├─ 本地预检(can_merge)           │
  ├─ 播放合并动画（乐观UI）         │
  ├─ POST /api/game/merge ────────►│
  │   { from, to, version }        ├─ 校验version（乐观锁）
  │                                ├─ 验证A、B存在且相同id+group_id
  │                                ├─ 验证下一级物品存在
  │                                ├─ 删除A、B，创建合并物品
  │                                ├─ 更新分数，version+1
  │                                ├─ 持久化
  │   ◄────────────────────────────┤
  │   { ok, result_id, score }     │
  ├─ 确认动画 → 数据落地          │
  │                                │
  ─── 或 ───                       │
  │   ◄── 400/409 error ──────────┤
  ├─ 撤销动画 → 物品弹回           │
```
