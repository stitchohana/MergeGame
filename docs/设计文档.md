# Merge Game 实现计划

## Context

从零开始构建一个 Godot 4 合成游戏。核心机制：7×9 固定格子棋盘，拖拽相同等级物品合并升级，点击发射器生成物品，发射器本身也可合成升级。所有物品通过 JSON 配置表定义。

## 架构概览

### 核心设计决策

| 决策 | 方案 | 原因 |
|------|------|------|
| 全局状态 | 4个 Autoload 单例 | 项目规模小，单例够用 |
| 物品模型 | 单一 `GridItem.tscn` + JSON 配置表驱动 | 所有物品数据从配置读取，改配置即改游戏 |
| 网格数据结构 | `Array[Array]` 二维数组 + Dictionary 反向映射 | 固定网格最快最直接 |
| 合并方式 | 单次合并，无连锁 | 玩家手动拖拽，一个操作只合一次 |
| 渲染体系 | 全部 Control 节点（无 Node2D） | 后续直接换 TextureRect 的 texture 即可替换美术资源 |
| 存档 | JSON 序列化 | 人类可读，易调试 |

### 配置表加载流程

```
Game启动
  → ConfigDatabase (Autoload) 读取 JSON
  → 解析 items.json → Dictionary (key=id, value=所有字段)
  → 构建快捷索引: by_level[type][level] = item_data
  → 提供 API: get_item_data(id), get_item_by_level(type, level), get_next_level_data(type, level)
```

**ConfigDatabase.gd API：**
```gdscript
func get_item_data(item_id: int) -> Dictionary                # 通过数字 id 查物品
func get_item_by_level(type: String, level: int) -> Dictionary # 通过等级查物品
func get_next_level(type: String, level: int) -> Dictionary    # 下一级物品
func roll_spawn(launcher_id: int) -> Dictionary                # 按权重随机生成物品
func get_game_config(key: String)                              # 获取游戏参数
```

**roll_spawn 实现逻辑：**
```gdscript
func roll_spawn(launcher_id: int) -> Dictionary:
	var data = get_item_data(launcher_id)
	var spawns: Array = data.spawns
	var total_weight = 0
	for s in spawns:
		total_weight += s.weight
	var roll = randi() % total_weight
	var accum = 0
	for s in spawns:
		accum += s.weight
		if roll < accum:
			return get_item_data(s.id)
	return get_item_data(spawns[-1].id)
```

### 合并时物品 ID 推导规则

拖拽 itemA(id=1, level=1) 到 itemB(id=1, level=1)：
1. MergeService 确认两者 level 相同且 type 相同
2. 目标等级 = level + 1
3. 调用 `get_item_by_level("regular", 2)` 获取新物品（id=2）
4. 创建新物品（id=2, level=2）
5. 移除 itemA 和 itemB，在目标位置放置新物品

### 发射器点击逻辑

点击发射器(id=101)：
1. GridView 调用 `ConfigDatabase.roll_spawn(101)` 按权重随机抽取
2. 例如抽到 id=1（概率 70%），返回鹅卵石数据
3. GridManager.find_nearest_empty(click_pos) 找最近空格
4. 在空格创建 id=1 的物品

### UI 架构（全部 Control 节点）

所有界面元素继承 `Control`，物品用 `TextureRect` 显示图标，后续只需替换 `assets/` 下的图片文件即可换皮。

**场景树结构：**
```
Main.tscn
└── Main (Control)                     [铺满视口]
	│
	├── TopBar (Control)               [顶部, h=100px]
	│   ├── ScoreLabel (Label)
	│   ├── HighScoreLabel (Label)
	│   └── SettingsBtn (Button)
	│
	├── GridView (Control)             [居中, 504x648]
	│   ├── GridBackground (TextureRect)
	│   ├── GridCells (Control)        [63 个子节点]
	│   │   └── GridCell (ColorRect/TextureRect) ...
	│   ├── ItemsLayer (Control)       [Z-index 高于格子]
	│   │   └── GridItem (TextureRect) ...
	│   ├── DragGhost (TextureRect)    [半透明, mouse_filter=ignore]
	│   └── HighlightLayer (Control)   [mouse_filter=ignore]
	│
	├── BottomPanel (Control)          [底部, h=80px]
	│   └── ItemCountLabel (Label)
	│
	└── Overlay (Control)              [覆盖全屏]
		├── PausePanel (Panel)
		└── GameOverPanel (Panel)
```

**GridItem 节点结构：**
```
GridItem (TextureRect)
  ├── texture = 物品图标（后续替换图片即可换皮）
  ├── stretch_mode = keep_aspect_centered
  ├── 附加脚本处理鼠标事件（gui_input）
  ├── LevelLabel (Label)               "Lv.1" 显示等级
  └── 区分：普通物品用 modulate 调色；发射器加装饰边框
```

**坐标转换公式（GridView 内部）：**
```gdscript
# 格子坐标 → UI 像素坐标
func grid_to_local(col: int, row: int) -> Vector2:
	return Vector2(col * CELL_SIZE, row * CELL_SIZE)

# 像素坐标 → 格子坐标（鼠标点击时用）
func local_to_grid(local_pos: Vector2) -> Vector2i:
	return Vector2i(int(local_pos.x / CELL_SIZE), int(local_pos.y / CELL_SIZE))
```

所有 GridItem 通过 `position` 属性定位在 `ItemsLayer` 内，无需全局坐标转换。

**拖拽实现（Control 原生）：**
- GridItem 的 `gui_input` 检测鼠标按下 → 开始拖拽
- GridView 的 `_input` 或 `_process` 中更新 `DragGhost.position`
- 鼠标松开时计算目标格子
- TextureRect 替换 sprite，拖拽更轻量

### 信号架构

```
GridItem.clicked → GridView._on_item_clicked       (点击发射器)
GridItem.drag_started → GridView._on_drag_started   (拖拽开始)
GridItem.drag_ended → GridView._on_drag_ended       (拖拽结束)

GridView.drop_validated → MergeService.try_merge()  (验证合并)

MergeService.merge_performed → GridView / TopBar    (合并完成更新)

GridManager.item_added → GridView                   (添加节点)
GridManager.item_removed → GridView                 (移除节点)

GameState.score_changed → TopBar                    (分数更新)
GameState.phase_changed → Main                      (阶段切换)
```

### 状态机

```
INIT → IDLE ↔ {DRAGGING, MERGING, SPAWNING, PAUSED} → GAME_OVER
```

IDLE 是中心状态，所有操作完成后回到 IDLE。合并期间输入被阻断。

## 实现顺序

### Phase 1: 数据层（先测试）
1. `project.godot` — 项目配置 + Autoload 注册
2. `Constants.gd` + `GridUtils.gd` — 常量和工具函数
3. 创建 3 个 JSON 配置表（game_config.json, items.json, initial_setup.json）
4. `ConfigDatabase.gd` — JSON 加载和查询 API（含单元测试）
5. `GridManager.gd` — 核心网格数据结构（含单元测试）
6. `GameState.gd` — 分数和阶段管理（含单元测试）
7. `MergeService.gd` — 合并逻辑（含单元测试）

### Phase 2: 网格视图
8. `GridCell.tscn` + `GridCell.gd` — 单个格子
9. `GridItem.tscn` + `GridItem.gd` — 物品节点（含点击/拖拽信号）
10. `GridView.tscn` + `GridView.gd` — 网格视图 + 拖拽交互
11. `Main.tscn` + `Main.gd` — 根场景，串联所有系统

### Phase 3: UI
12. `TopBar.tscn` + `TopBar.gd` — 分数显示
13. `BottomPanel.tscn` + `BottomPanel.gd` — 物品计数
14. `Overlay.tscn` + `Overlay.gd` — 暂停/结束弹窗

### Phase 4: 特效与音效
15. 合并/生成动画特效
16. 音效接入

### Phase 5: 存档
17. `SaveData.gd` + `SaveManager.gd` — 存取档

## 验证方式

1. `godot4 --path .` 启动后看到 7×9 网格 + 初始物品
2. 拖拽鹅卵石(id=1)到相邻鹅卵石 → 合成为石块(id=2)
3. 点击基础发射器(id=101) → 大概率出鹅卵石，小概率出石块或自身
4. 拖拽两个同级发射器 → 合成为高级发射器
5. 高级发射器点击 → 按配置权重随机生成物品
6. 在 scenes/inspector 中修改 GridItem 的 TextureRect 的 texture → 界面即时更新，无需改代码
7. 网格填满且无可合并时 → Game Over
8. 修改 items.json 中的数值 → 重启游戏后生效
