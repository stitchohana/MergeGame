# 商城刷新与限购实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**目标：** 每件商品每轮限购 5 次，100 灵石手动刷新，4 小时自动刷新；刷新包含当前订单所需普通物品，排除配方产物。

**Architecture:** 服务端在玩家存档保存商城快照、购买次数和刷新时间，客户端只展示和提交操作。

**Tech Stack:** TypeScript、Godot 4/GDScript、JSON/XLSX 配置、现有 HTTP 接口和冒烟测试。

---

**设计：** 玩家存档保存商城轮次、商品、购买次数和下次刷新时间。服务端按刷新时的订单生成商品快照，普通订单物品直接加入，配方订单递归加入普通材料，按 ID 去重。商店表仅提供售价，不额外加入无关商品。未配置售价的订单商品使用物品 value，最低 1 灵石。手动刷新重新开始 4 小时计时。离线时间计入，重新请求时结算；打开商城时倒计时到零主动请求自动刷新。

2026-10-20 修正：移除固定商品兜底；旧存档读取时清理 `order_required=false` 的商品，保留其余商品次数与原刷新时间。回归覆盖严格订单商品集合、无订单空列表、无关商品无法购买及旧存档清理。

1. 新增商城服务，生成商品快照、处理自动/手动刷新和购买额度。100 灵石刷新费用通过 shop.xlsx 的 settings 工作表往返导出。
2. 商城接口使用现有玩家串行操作队列并保存存档；带商城 revision 防止旧轮次按钮误买及刷新请求重复扣费。
3. CloudService 增加完整商城信息、刷新结果及失败信号。商城展示限购、订单需要标记、倒计时、付费刷新和加载/请求互斥。
4. 增加服务端额度/订单/配方/时钟/持久化/失败/并发回归检查和 Godot UI 冒烟检查，执行类型检查与可用的 Godot 校验。
