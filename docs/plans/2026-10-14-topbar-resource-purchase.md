# TopBar 资源购买

用户需求：体力、灵力加号打开确认购买弹窗；灵石加号打开现有商城。灵力购买按获得灵力处理。用户确认价格每次增加 100 灵石，每日重置。

规则：两种资源分别计数，首购 100 灵石，每次获得 100 点；按现有 reset_hour（北京时间 5 点）重置。付费资源允许超过恢复上限，保证完整获得 100 点，体力奖励沿用倍率更新逻辑。

实现步骤：
1. 新增配置 resource_purchase.base_cost、cost_increment、amount，同步 game_config.xlsx 和 JSON。
2. 新增 ResourcePurchaseService，服务器报价、余额校验、独立每日计数和请求幂等；旧存档默认为零次。API 通过玩家操作队列串行结算，在状态副本上计算并持久化后返回。
3. TopResource 发出加号信号，TopBar 接入两个购买弹窗和商城。购买弹窗复用 ConfirmPopup，显示价格、数量、递增及重置说明，等待响应时禁用确认和取消。
4. CloudService 获取报价并提交购买，成功同步体力、灵力、灵石与体力倍率；失败不本地扣款，网络失败可重试同一个请求。
5. 校验服务端余额不足、并发、失败回滚、重放、每日边界、独立计数、重登；运行 TypeScript 检查、Godot 解析与按钮/弹窗冒烟。

验证结果：`npm run worker:check` 通过；服务端 `resource_purchase_smoke` 通过，覆盖价格、05:00 重置、独立计数、重放、并发、保存失败回滚及持久化报价。tsx 的编译子进程在沙箱内无法启动，改用 TypeScript 直接输出 JavaScript 后执行测试。全量严格类型检查仍报告现有引擎/路由的类型问题，新增购买代码没有类型诊断。

Godot `TopBarResourcePurchaseSmoke.tscn` 通过，覆盖三个加号、报价及离线提示、资源同步、关闭释放和余额更新后的同一请求重试。导入及运行日志没有脚本错误；环境存在根证书读取提示。未部署服务端。
