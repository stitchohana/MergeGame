# 秘境 Boss 九格特殊迷雾

Boss 本格及周围八格组成 3×3 特殊迷雾。普通相邻合成和推进揭雾不能解锁；当前视口全部小怪死亡时，在该次结算中统一揭开九格。小怪计数包含迷雾中的小怪及重叠区域遗留小怪，与现有 Boss 前置条件一致。

服务端根据配置中的 Boss 坐标推导封印区域；导表和服务端共同校验九格合法且小怪可在封印外到达。隐藏视图仅返回坐标、fog 和 special_fog，不暴露底层内容。揭雾保存原物品 UID、等级、固定属性和 Boss，并在小怪奖励投放前完成。没有存档迁移、读取修复或新配置字段。

客户端沿用原棋格，以紫色迷雾和“封”字标识，点击显示解锁条件及剩余小怪数。普通棋格的拖拽、合成和动画规则保持现有实现。

验证结果：

- Python 配置校验及非法封印布局测试通过。
- 服务端六关封印测试通过：相邻合成、只读预览、隐藏内容、部分提交、最终解锁、保存重开、请求重放、下一关封印。
- 通用秘境结算及掉落动画数据测试通过。
- Godot 界面测试及截图检查通过，九格标识清晰且不展示底层内容。
- 真实 HTTP 拖拽战斗测试通过：第一只小怪后封印保持，第二只后九格解锁；重开保持解锁；Boss 可继续提交并推进。
- 使用实际订单补给及操作完整走通六关：2318 次补给、8888 次合成、35400 次操作，合成奖励零丢失。该数字为测试求解路径，非最优成本。
- 服务端全量 TypeScript 严格检查仍存在其他模块错误（game_engine、routes、storage 和 Worker 类型），本次 secret_realm.ts 无类型错误；测试构建与上述运行验证完成。
