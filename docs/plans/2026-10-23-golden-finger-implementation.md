# 三法宝实施计划

**Goal:** 实现聚宝盆、万象炉、太虚时砂，储物袋旁三个入口、介绍与使用弹窗，修为等级 2/4/6 解锁。

**Architecture:** 服务端独立 GoldenFingerService 维护配置、报价、每日额度、操作回执和单步回溯快照；所有法宝变更复制后校验并原子保存。Godot 通过既有请求队列同步权威状态，入口打开介绍后进入操作。

**Tech Stack:** Godot 4.6 GDScript、TypeScript、现有版本化存储、JSON/XLSX。

1. 新增 golden_finger.json、独立工作簿与双向导表，纳入 Worker 和客户端配置。默认免费次数 1/3/1，购买上限 2/5/2；聚宝盆加次费用按境界内最大直接售卖净收益校准，其他两件基础价可改表。
2. 实现服务与状态、预览/使用/加次接口，严格检查解锁、普通材料生产来源、UID、周期、报价、版本、价值与白名单。回执跨日保留，失败不保存部分状态。
3. 接入合并、生成、出售的最近一次可逆操作记录；回溯窗口 60 秒，保留随机序列、UID 计数与法宝次数，其他相关变化使快照失效。
4. 新增储物袋左侧三入口、介绍弹窗及操作界面，接入次数显示、加次、产物预览、时间模式、锁定状态、请求互斥和失败重试。
5. 增加服务端行为/路由测试和 Godot UI smoke；运行导表往返、Worker 检查、相关回归与实际渲染，修复新增问题并记录结果。

在当前未提交改动基础上局部实施，不自动提交、部署或重置现有文件。

## 实施结果

- 已交付以上五项核心功能。入口顺序为聚宝盆、万象炉、太虚时砂、储物袋；锁定状态仍可查看介绍，服务端使用与加次同时检查 2/4/6 级门槛。
- 万象炉暂采用多件材料按价值兑换一个目标，超额不找零。聚宝盆改为拖入材料，两个产物优先飞入棋盘，溢出进入已有暂存区；万象炉产物直接暂存；材料池从已解锁生产来源中生成，只允许普通材料。客户端提供位置与价值，使用前明确确认。
- 太虚时砂的回溯恢复全量相关玩家状态，包括自动结算的任务与奖励；保留单调 UID、随机序列、法宝次数及请求回执。自然充能/体力恢复、其他相关状态变化可能使旧快照失效，窗口是最长 60 秒。加速只完成等待，不自动领取成品。
- 使用与购买带版本、周期、报价和请求 ID；回执最多保留 128 条，旧回执淘汰后仍受版本检查保护。跨日重放不重复发奖。保存失败不落部分数据；客户端保留不确定请求以重试。
- 同账号重新登录保留不确定请求，切换账号清空法宝缓存。客户端按存储修订号过滤旧响应，使用成功替换权威棋盘并重建制作计时。
- `golden_finger.xlsx` 包含 artifacts/realms/settings；最后一个修为区间覆盖第 20 阶段化神前期，当前材料最高配置为 16 级。新增境界需同时扩展区间。解锁等级/名称与覆盖范围在导表和启动校验。
- 未实现讨论稿中的订单缺料专用筛选、每项订单需求徽标和万象炉、太虚时砂的专属结果动画；现用预览、二次确认及到账提示完成核心操作。长期经济与每日福利预算仍需实玩调优。
